# Thread 25 — Geometric Pullback Visualization v0.01

## Milestone

Thread 25 consumes the admitted deterministic finite Thread 24 sample

S_0 subset X_0

and constructs finite recursive pullback samples

S_(n+1) = P_D^(-1)(S_n),
P_D(z1,z2,z3,z4) = (z1^D,z2^D,z3^D,z4^D).

The canonical runtime uses D=2 and the canonical Thread 24 seed contains 512 full-coordinate-distinct points.

This artifact does not claim S_n = X_n. It renders only the finite geometric pullback induced from the admitted seed.

## Authority

- torusCoordinatePower as the coordinatewise torus power map;
- concreteLevel_succ as the concrete pullback recurrence;
- natCard_torusPowerFiber as the exact set-cardinality theorem |P_D^(-1)(y)| = D^4 for positive D.

TorusPowerFibers.lean explicitly does not promote this cardinality result to covering-space degree, finite étale degree, or algebraic-geometric map degree. Thread 25 preserves that boundary.

Therefore:

- preimage point: admitted;

- root multi-index: deterministic enumeration metadata only;
- branch: not claimed as an analytic branch;
- sheet: not materialized;
- covering structure: not claimed.

## Constructor

For each nonzero complex parent coordinate x = r exp(i theta), with principal argument supplied by signed-zero-normalized Math.atan2, the enumerator generates

r^(1/D) exp(i (theta + 2 pi k) / D), k = 0,...,D-1.

All four coordinate root sets are combined in lexicographic multi-index order (k1,k2,k3,k4). The complete one-parent fiber therefore contains the derived cardinality D^4. Principal-root-only truncation is forbidden.

The tuple (k1,k2,k3,k4) is not a global sheet identity and is not asserted to vary continuously across parent points.

## Numerical contracts

Thread 24 membership remains governed by its own versioned W_kappa residual policy.

Thread 25 introduces a separate power-map residual policy:

|y_i^D - x_i| <= 5e-13 + 5e-13 max(1, |x_i|).

It is used only to support the numerical claim that a generated child maps back to its declared parent. It is not a W-membership tolerance and is not a geometric metric.

Every generated positive-depth point is also lifted through P_D^n to the base and rechecked with the inherited Thread 24 membership policy, implementing the numerical path W_kappa(P_D^n(z)) approximately lambda.

## Materialization policy

The production policy is exact_hard_cap with 10,000 generated points per next level.

For the canonical seed and D=2:

- depth 0: 512 points;
- depth 1: 512 * 2^4 = 8192 points;
- depth 2 would require 8192 * 2^4 = 131072 points.

The canonical browser therefore materializes depth 0 and complete depth 1 only. A request whose exact next level exceeds the cap is rejected before generation; no partial parent fiber and no deterministic truncation is rendered.

Recursive correctness through depth 2 is verified separately with a one-seed fixture:

- depth 0: 1;
- depth 1: 16;
- depth 2: 256.

## Rendered mark meaning

A positive-depth mark means one deterministic finite geometric preimage point generated by recursively enumerating complete admitted coordinate-power fibers from an admitted X_0 seed, numerically validated against its declared parent, and displayed under the inherited z1 Cartesian projection.

It does not mean:

- a complete X_n;
- a sheet;
- a connected component;
- a covering chart;
- a branch locus;
- a singularity;
- a metric density;
- a source self-intersection.

## Renderer

Canonical depth 1 uses SVG. At 8192 source marks it preserves one DOM mark per geometric model object, source ID, parent ID, ancestor X_0 sample ID, root multi-index, depth, and projected-overlap count.

Depth 2 for all 512 seeds is intentionally not DOM-materialized.
